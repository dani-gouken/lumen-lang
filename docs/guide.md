# Writing and Running Lumen Programs

A practical guide to what works today. For the full syntax see the [language spec](language-spec.md); for how the compiler is built see the [pipeline](compilation/pipeline.md).

## Setup

```bash
make build            # produces ./lumen
```

or run without building: `go run ./cmd/lumen <command>`.

## Hello, World

```lumen
// hello.lum
fn main() -> Int {
    println("Hello, Lumen!");
    return 0;
}
```

```bash
./lumen run hello.lum
```

Every program needs a `main` function without parameters. If it returns an `Int`, that becomes the process exit code.

## Commands

| Command | What it does |
|---------|--------------|
| `lumen run file.lum` | Compile and run |
| `lumen build file.lum out.lc` | Compile to a bytecode file, run later with `lumen exec out.lc` |
| `lumen build file.lum out.lasm` | Write a readable listing of the generated bytecode |
| `lumen ir file.lum` | Print the intermediate representation |
| `lumen lumdbg file.lum` | Step through the program in the debugger ([debugger.md](debugger.md)) |
| `lumen asm` / `disasm` / `exec` / `runasm` | Work with hand-written assembly ([assembly.md](assembly.md)) |

Exit codes: `0` on success (or the `Int` returned by `main`), `1` for a compile error, a runtime error or a usage error. Diagnostics go to stderr, program output to stdout.

A `.lasm` file produced by `build` is a listing for reading. It is not accepted back by `lumen asm`, because the disassembler prints long jumps in an annotated form.

## A Tour of the Language

The programs in [`examples/`](../examples) are runnable versions of what follows.

### Values and variables

```lumen
let count = 3;              // type inferred: Int
let ratio: Float = 0.5;     // or stated
let name = "lumen";
let ready = true;
let nothing: Int? = null;   // T? admits null

count = count + 1;          // reassignment
{
    let count = 100;        // a block has its own scope
}
```

There is no implicit conversion between `Int` and `Float`: `1 + 2.5` is a compile error.

### Strings

```lumen
let s = "foo" + "bar";      // concatenation
s.length                    // 6
s[0]                        // "f" (a one-character string)
s == "foobar"               // compared by content
"a" < "b"                   // ordered
toString(42) + "!"          // convert other values first
```

### Control flow

```lumen
if n < 0 { ... } else if n == 0 { ... } else { ... }

while i < 10 {
    if i == 5 { break; }
    i = i + 1;
}

for item in [1, 2, 3] { ... }     // arrays
for char in "abc" { ... }         // strings

match n {
    case 0: { println("zero"); }
    case 1: { println("one"); }
    default: { println("many"); }
}
```

`&&` and `||` skip their right side when the left side decides the result. `a ?? b` is `a` unless it is `null`.

### Functions

```lumen
fn add(a: Int, b: Int) -> Int {
    return a + b;
}

fn log(prefix: String, values: ...Int) -> Void {     // variadic
    println(prefix, values.length, values);
}

fn first<T>(items: [T]) -> T {                       // generic
    return items[0];
}

log("got", 1, 2, 3);
first<Int>([7, 8]);          // type arguments are written out
```

Functions are values: they can be stored in variables, passed and returned.

### Arrays

```lumen
let xs = [10, 20, 30];
xs[0] = 11;                 // replace an element
push(xs, 40);               // grow
xs.length                   // 4
```

All elements have the same type. Reading or writing an index that does not exist is a runtime error.

### Structs, traits and methods

```lumen
struct Point { x: Int; y: Int; }

trait Shape {
    fn area() -> Int;
}

impl Shape for Point {
    fn area() -> Int { return self.x * self.y; }     // `self` is implicit
}

impl Point {                                         // methods outside a trait
    fn moved(dx: Int) -> Point { return Point { x: self.x + dx, y: self.y }; }
}

fn show(s: Shape) -> Void { println(s.area()); }     // any struct implementing Shape

let p = Point { x: 2, y: 3 };
p.x = 5;
show(p.moved(1));
```

Structs are references: `let q = p;` makes `q` and `p` the same value.

Inside the header of `if`, `while`, `for` and `match`, wrap a struct literal in parentheses: `if (Point { x: 1, y: 2 }).area() > 0 { ... }`.

### Closures

```lumen
fn makeCounter() -> fn() -> Int {
    let count = 0;
    return fn() -> Int {
        count = count + 1;      // captured by reference
        return count;
    };
}

let next = makeCounter();
next();     // 1
next();     // 2
```

A closure shares the variables it captures with the function that declared them, and keeps them alive after that function returns.

### Builtin functions

| Function | Description |
|----------|-------------|
| `print(values...)` | Write the values separated by spaces |
| `println(values...)` | Same, followed by a newline |
| `toString(value)` | The text `print` would write, as a `String` |
| `push(array, value)` | Append to an array |

## Reading Errors

### Compile errors

```text
[ERROR] E2001: cannot assign type int to string
  --> main.lum:8:25
   |
 8 |     let label: String = double(4);
   |                         ^^^^^^
   |
   = Suggestion: Ensure the value is of type string
```

The code (`E2001`) identifies the kind of error; [compilation/diagnosis.md](compilation/diagnosis.md) lists them all. The first digit tells which stage found it: `0` syntax, `1` names, `2` types, and so on.

The compiler reports the errors of one stage at a time. After fixing syntax errors you may see type errors that were not shown before; that is expected.

### Runtime errors

```text
Runtime error: index out of bounds: 7 (length 3)
  at main.lum:3:17 in function 'pick'
        return items[index];
                    ^
```

The program stops and exits with code 1.

## Not Supported Yet

These are rejected with a clear error rather than miscompiled:

*   `import` and programs spanning several files
*   `enum`
*   `match` on types (`case Int:`)
*   inferring type arguments (`first([1])` must be `first<Int>([1])`)

Things to be aware of:

*   **Type checking is partial.** Results of method calls, generic values, optionals and trait-typed values are checked when the program runs, not when it compiles.
*   **`const` is not enforced** yet; a `const` can be reassigned.
*   **A function that falls off its end returns `null`**, even if it declares a return type.
*   **Closures created in a loop share the loop body's variables.** Pass the value through a function parameter to give each closure its own copy.
*   **Size limits:** 256 registers per function, 256 distinct constants and 256 functions per program. Very large functions may need to be split.

The status table in the [language spec](language-spec.md#13-implementation-status) lists what works; [missing.md](missing.md) is the full inventory of what does not, including `+=`/`++`, the index in `for` loops and arrays with a size.
